# Олимпиадный навигатор

Проект команды **CU++** для школьников, которые планируют поступать по олимпиадам. В мини-приложении MAX можно выбрать программы вузов, посмотреть условия БВИ и собрать список олимпиад. Бот напоминает о сроках и позволяет управлять этим списком прямо в чате.

[Открыть приложение](https://max-hackathon.centraluniversity.dev) · [Перейти к боту](https://max.ru/t529_hakaton_max_bot)

## Возможности

- Поиск программ по вузу, городу, направлению и предметам. Количество выбранных программ не ограничено.
- Каталог олимпиад с уровнями РСОШ, условиями БВИ, сроком действия диплома и ссылками на источники.
- Личный список олимпиад и календарь. Год поступления рассчитывается по классу.
- Напоминания в MAX за неделю и за сутки до известного срока, тихие часы и перенос сообщения на час.
- Отметки о регистрации и завершении участия доступны и в чате, и в приложении.

## Запуск

Нужны Docker и Docker Compose v2.

```bash
cp .env.example .env
docker compose up --build -d --wait
```

Приложение откроется на http://localhost:8080. Compose поднимет PostgreSQL, API и frontend, миграции выполнятся автоматически. Порт можно изменить через `FRONTEND_PORT` в `.env`.

По умолчанию включено браузерное демо: оно создаёт отдельный профиль без привязки к MAX. Сообщения в чат в этом режиме не отправляются.

Для запуска бота заполните `APP_BOT_TOKEN` и `APP_BOT_USERNAME` в `.env`, затем выполните:

```bash
docker compose --profile max up --build -d --wait
```

Для мини-приложения нужен публичный HTTPS-адрес, привязанный к боту в MAX. Интерфейс и `/api` должны быть доступны на одном домене. Бот получает сообщения через long polling, webhook не требуется. Токен хранится только на сервере.

Проверка готовности: `curl http://localhost:8080/api/v1/healthz/ready`. Остановка: `docker compose down`. База сохраняется в Docker volume.

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Начать работу, открыть меню |
| `/profile` | Выбрать класс и программы вузов |
| `/catalog` | Найти олимпиаду; можно также написать её название в чат |
| `/track` | Открыть свой список олимпиад |
| `/deadlines` | Посмотреть ближайшие сроки |
| `/settings` | Настроить напоминания |
| `/stop`, `/resume` | Отключить или включить напоминания |
| `/quiet 22 8` | Установить тихие часы с 22:00 до 08:00 |
| `/timezone Asia/Yekaterinburg` | Изменить часовой пояс |

В карточке олимпиады можно посмотреть условия, добавить её в список и отметить регистрацию. Регистрироваться на олимпиаду нужно самостоятельно на сайте организатора. Для демонстрации доставки есть кнопка «Тест сообщения в чат» при включённом `APP_DEMO_ENABLED`.

## Данные

В каталоге 32 олимпиадных профиля по 12 предметам и девять программ семи вузов: ВШЭ, ИТМО, Центрального университета, МИФИ, МФТИ, МГТУ им. Баумана и МГУ.

Данные проверены 30.09.2026 и хранятся в [catalog.py](backend/src/app/route/catalog.py). У записей указаны источники и дата проверки. Автоматического обновления с сайтов вузов пока нет.

Уровни РСОШ относятся к перечню 2025/26. Условия БВИ проверены для части программ ВШЭ по правилам приёма 2026 года; на будущие кампании они автоматически не распространяются. Для остальных программ неподтверждённые условия не указаны. Напоминания создаются только при наличии точной даты и времени. Региональные сроки ВсОШ нужно уточнять в школе.

## Устройство проекта

Backend: Python, FastAPI, SQLAlchemy, PostgreSQL и maxapi. Frontend: React, TypeScript и Vite. Nginx раздаёт интерфейс и проксирует API. Бот и API используют общую базу профилей, отметок и очереди напоминаний.

- `backend/src/app/route/`: каталог, авторизация и работа с профилем и олимпиадами.
- `backend/src/app/bot/`: команды, кнопки и отправка напоминаний.
- `backend/src/app/api/`: HTTP API.
- `backend/migrations/`: миграции базы.
- `frontend/src/`: интерфейс и клиент API.

Вход через MAX проверяется на сервере по подписи `initData`. Удаление профиля удаляет также его отметки, сессии и очередь сообщений. После неопределённого результата отправки бот не повторяет сообщение автоматически, поэтому доставка не гарантируется при сбоях MAX.

## Разработка

Нужны Python 3.13+, uv, Node.js 24+ и pnpm. Backend локально использует SQLite:

```bash
cd backend
cp ../.env.example .env
uv sync --locked --all-groups
uv run alembic upgrade head
uv run api
```

Frontend запускается в другом терминале:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Vite откроет http://localhost:5173 и направит запросы `/api` на `localhost:8000`. Для запуска бота отдельно выполните `uv run bot` из `backend/` с настроенным токеном.

## Доступ к API для жюри

Для ручной проверки выдан отдельный Bearer-токен. Его можно вставить в **Authorize** на
[странице API](https://max-hackathon.centraluniversity.dev/api/docs), без префикса `Bearer`.
Вход через MAX и запрос `/auth/demo` не нужны.

```bash
export JURY_API_TOKEN='вставьте выданный токен'
API=https://max-hackathon.centraluniversity.dev/api/v1

curl "$API/me" -H "Authorization: Bearer $JURY_API_TOKEN"

curl -X PUT "$API/track/vsosh-math" \
  -H "Authorization: Bearer $JURY_API_TOKEN"

curl -X PATCH "$API/track/vsosh-math" \
  -H "Authorization: Bearer $JURY_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"status":"registered"}'

curl "$API/track" -H "Authorization: Bearer $JURY_API_TOKEN"
```

Токен открывает отдельный тестовый профиль, общий для всех проверяющих с этим токеном.
При первом запросе он создаётся с 10 классом и программой ПМИ ВШЭ. Профиль можно менять
через `PUT /me`. Данные пользователей MAX недоступны, сообщения в MAX не отправляются.
Каталог доступен без токена: `GET /catalog`.

`DELETE /me` сбрасывает тестовый профиль вместе с отметками и уведомлениями. Следующий
запрос с тем же токеном создаст его заново. Для проверки уведомлений доступен
`POST /demo/events` с телом `{"olympiad_id":"vsosh-math","kind":"registration"}`;
сначала добавьте олимпиаду в список, оставив статус `planned`. Тестовые уведомления
в профиле жюри включены по умолчанию. Этот запрос требует `APP_DEMO_ENABLED=true`.

На сервере токен задан в `APP_JURY_API_TOKEN`, в репозиторий его значение не включается.
Пустое значение отключает этот способ входа. Для замены или отключения измените `.env`
и выполните `docker compose up -d api`. Токен действует до замены или отключения,
перезапуск API не сбрасывает профиль.

## Проверки

Из `backend/`:

```bash
uv run ruff check .
uv run pyright
uv run pytest
uv run python tools/generate_openapi.py --check
```

Из `frontend/`:

```bash
pnpm lint
pnpm typecheck
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Браузерные тесты проверяют мобильный и настольный интерфейс. Они используют отдельную SQLite-базу и не отправляют сообщения в MAX.

[DATA-API.yaml](DATA-API.yaml) описывает сценарий проверки для организаторов: вход, сохранение профиля, добавление олимпиады, тестовое уведомление, отметка регистрации и удаление тестового профиля. Для него нужен `APP_DEMO_ENABLED=true`. Прогнать сценарий на локальном стенде можно из `backend/`:

```bash
uv run python tools/check_scenario.py --base-url http://localhost:8080/api
```

Контракт API: [openapi.yaml](backend/spec/openapi.yaml), интерактивная документация: `/api/docs`. После изменения API обновите контракт командой `uv run python tools/generate_openapi.py` из `backend/`, затем клиент командой `pnpm generate:api` из `frontend/`.
